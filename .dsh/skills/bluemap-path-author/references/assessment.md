# 学习路径摸底：题型、评分、停止规则

目标：用 6–8 道题把每个探测点放到 0–5 的某一档，而不是把整门课考一遍。
评分语义必须和 BlueMap 一致（`src/domain/types.ts` 的 `MASTERY_LABEL` / `MASTERY_HINT`）。

## 1. 0–5 判据

| 分数 | 名称 | 判据 | 你要听到什么 |
| --- | --- | --- | --- |
| 0 | 未知 | 没接触过，或答不出 | 「没学过」「不知道从哪开始」 |
| 1 | 接触 | 看过、听过，但说不清 | 能蹦名词，解释不成句 |
| 2 | 理解 | 能用自己的话解释核心概念 | 有类比、能说清「解决什么问题」 |
| 3 | 应用 | 能在给定场景下独立做对 | 步骤正确，能处理常规情况 |
| 4 | 迁移 | 换个新场景/新项目仍然能用 | 能排错、能权衡、能指出边界 |
| 5 | 教学 | 能讲给别人听并回答追问 | 有结构、有取舍、能接住「为什么」 |

### 不要给 4 分的情况

- 只背出定义，没做过。
- 只做对选择题。
- 只说「用过」「看过教程」。
- 答对了，但说不出为什么，也换不了场景。

### 5 分很少给

需要「讲解 + 追问」两个证据：能先把概念讲给新手，再回答一个反例或边界问题。一次回答不给 5。

## 2. 题目设计

每轮 3–4 题，总题数 6–8。题型按目标层级选：

| 目标层级 | 题型 | 示例 |
| --- | --- | --- |
| 2 | 解释 | 「不用背定义：让一个没学过的人用一句话理解 X，你会怎么说？它解决什么问题？」 |
| 3 | 应用 | 「给定这个场景（具体输入/约束），你会先做什么、再做什么？写出关键步骤或输出。」 |
| 4 | 迁移/排错 | 「把场景换成 Y，X 还成立吗？哪里先坏？你怎么验证？」 |
| 5 | 教学 | 「如果新手追问『为什么不能直接……』，你怎么答？」 |
| 证据 | 作品 | 「有没有相关代码/项目？贴 10–30 行关键部分或 README，我按代码问。」 |

### 避免

- 是非题、选择题。
- 名词默写、能直接搜到答案的题。
- 一题问三件事。
- 先给答案再问。
- 用「这很简单」施压。
- 把评分标准先贴出来。

## 3. 选探测点

- 先在心里列 8–12 个候选节点，算每个节点的下游数；优先问「下游多 + 基础」的 4–6 个。
- 每个探测点至少能区分相邻两档；不要问所有节点。
- 目标/基础分叉用一道「你做过什么」题决定 track。
- 已掌握锚点最多 3–5 个；不要为了显得完整把整张图都测一遍。
- 用户有现成作品时，优先按作品问，而不是从零出题。

## 4. 评分规则

- 以回答为准，不以自评为准；自评只用来选探测点。
- 同一节点同时有问答分和作品分时取较小值（与 app 的 min 规则一致），不要取平均；摸底本身只给一个分。
- 不确定时低一档；宁可多学一个节点，不要跳过基础。
- 未探测的节点一律 0，不猜 3。
- 4 级以上要写一句「凭什么」：新场景 / 排错 / 权衡 / 教学。
- 5 级只在能讲清并接住追问时给。
- 如果用户答得漂亮但明显背过，换一个场景再问一次；仍对才给 4。

## 5. 停止规则

满足任一即停：

- 每个探测点都能落在 ±1 档；
- 2 轮用完（总题数 6–8）；
- 用户说「直接生成 / 够了」；
- 继续问的边际信息小于打扰成本。

## 6. 结果到图的映射

| 分数 | 图上的动作 |
| --- | --- |
| 4–5 | 已掌握锚点；保留节点，跳过补救子节点；不要给它加「入门」前置 |
| 3 | 保留；压缩 hours；加一个应用型 checkpoint；不要跳过 |
| 0–2 | 插入 1 个前置补丁节点；原节点后移；补丁节点 2–4h |
| 分支 | 只保留匹配 track 的节点；另一条不生成，避免「看起来什么都要学」 |

补丁节点也要有明确验收标准，不要叫「补基础」；写「能独立完成 X」。
锚点最多 3–5 个；不要把整张图都标成已掌握，否则 frontier 会消失。

## 7. 可追溯

- 在对话里维护一张表：题号 | 节点 | 分数 | 依据（一句话）。
- 最终摘要里写「为什么这个节点是 3 分」，让用户能反驳。
- 不要把问答记录写进 bundle（`aiQuiz` 会被导入丢掉）；导入后用 app 的 AI 问答继续积累证据。
- 如果用户提供了作品/代码，优先按作品评分；作品比口头回答强。

## 8. 里程碑路径的 intake（不做摸底）

问 4–6 个：

1. 终点交付物是什么？谁验收？
2. 截止日 / 每周投入？
3. 已有基础 / 作品？
4. 硬约束（预算/设备/团队/合规）？
5. 验收标准（可演示 / 可运行 / 可量化）？
6. 最大的风险是什么？

然后倒推 4–6 个阶段，每个阶段写「验收证据」，不要写「学习内容」。
阶段门用 `milestone`，产出用 `project`，验收用 `checkpoint`；阶段之间用 `hard` 边。
